`astra-*` runs GPT-6.2 Astra and `sol-*` runs GPT-6.2 Sol. Both keep their existing
efforts from medium through ultra; the seat names stay the same.

| Name | Was | Now |
|---|---|---|
| `astra-*` | GPT-6 Astra | GPT-6.2 Astra, medium … ultra |
| `sol-*` | GPT-6.1 Sol | GPT-6.2 Sol, medium … ultra |
| `gpt-6.2-astra-*` | unavailable | GPT-6.2 Astra, medium … ultra |
| `gpt-6.2-sol-*` | unavailable | GPT-6.2 Sol, medium … ultra |
| `gpt-6-astra-*`, `gpt-6.1-sol-*` | pinned to their named models | unchanged |
| `gpt-6-sol-*`, GPT-5.6 pinned names | pinned to their named models | unchanged |
| `luna-*` | GPT-6 Luna | unchanged |
| `terra-*` | GPT-6.1 Terra | unchanged |

A thread that ran on GPT-6 Astra or GPT-6.1 Sol reads back under its pinned name,
such as `gpt-6-astra-high` or `gpt-6.1-sol-high`. `codex_poll` and `codex_fork` report
the model it really ran on, and a fork stays there. Threads on GPT-6.2 Astra and Sol
read back under their family names.

Both 1M-context scripts now raise GPT-6.2 Astra and Sol to the existing 950,000
target. Their live check prefers GPT-6.2 Astra, then GPT-6.2 Sol, then the previously
listed models in their existing order. Each model retains its own prefix match.
GPT-6.2 Sol ships at a 500,000 window and GPT-6.2 Astra at 272,000; both ship with
an 872,000 ceiling.

A catalog built before 2026-11-17 hides these models until the 1M-context script is
re-run: the saved catalog is also codex's model list.
