Windows support.

The bridge now installs and runs on Windows (x64 and ARM64) alongside macOS: same
`.mcpb`, same six tools, same wire. `codex app-server` ships natively on Windows and
speaks the same UTF-8 JSON-RPC, so nothing about how you use the bridge changes.

## Windows: enable codex's sandbox first

codex ships its Windows sandbox switched off, and with it off it would run every
command with no filesystem boundary. The bridge refuses to dispatch until codex
reports the sandbox ready — `codex_check` shows `windows_sandbox` and the fix. Enable
it once in `%USERPROFILE%\.codex\config.toml`:

```toml
[windows]
sandbox = "unelevated"
```

No restart needed — the bridge asks codex for the current setting before every thread
it starts or resumes. Requires Windows 10 1809 or later and codex 0.153.1 or newer.

## Also in this release

- `scripts/enable-1m-context.ps1`: the context-window script for Windows — same
  behaviour and checks as the bash one, needs only PowerShell and codex.
- UTF-8 on every pipe and file the bridge touches, whatever the system locale.
- Whole drives and `%SystemRoot%`, `%ProgramFiles%`, `%ProgramData%` are refused as
  workspaces, as `/`, `~` and the system directories already were on macOS.
- A thread resumed from another client is held to the same workspace rule as one the
  bridge starts, before it can be steered or given a new turn.
- `codex_approve`'s `allow_class` was described as session-scoped. It writes an allow
  rule into codex's execpolicy: it persists across sessions, and commands it matches
  run outside the sandbox from then on. The description now says so.
- On exit the bridge closes app-server's stdin and waits for it, instead of leaving
  the child to notice on its own.
- CI runs the codex-free tests on Windows as well as Linux, and checks the packed
  `.mcpb` it uploads — both platforms named, the Windows interpreter override, the
  tool list and version matching the server — so the one bundle stays installable on
  both.
- The manifest now lists all six tools; `codex_compact` was missing from the install
  preview.
- MCP's `notifications/initialized` handshake is no longer logged as a failed
  notification on every connect.

Install: download `claude-codex-bridge-v0.13.0.mcpb` below. macOS: double-click it.
Windows: Claude Desktop → Settings → Extensions → Advanced settings → Install
Extension, from a local folder — Desktop refuses files on network paths, and Windows
has no `.mcpb` file association. Then restart Claude Desktop. Needs Python 3 on the
machine (`python3` on macOS, `python` on Windows) and codex installed before Desktop
starts. Prerequisites and the full documentation are in the
[README](https://github.com/Alexander-Stulov/claude-codex-bridge#readme).
