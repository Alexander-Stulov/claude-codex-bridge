`codex_poll` now names the files a turn produced, whatever their type, and copies them to
a folder you name.

| Area | Was | Now |
|---|---|---|
| Files codex reports writing: patches, and files its tools save, some outside `cwd` | Counted or not returned | Listed in `output_files` with `source: reported` |
| Files written by commands, such as a script's PDF or deck | Not reported | Listed with `source: modified_during_turn` when they are under `cwd` |
| Getting a file to the caller | Ask codex to copy it, which failed when codex did not know where its own tool saved it | `copy_to` on `codex_poll`: the bridge copies the listed files itself |

Every file type is handled the same way. `modified_during_turn` means the file changed
while the turn ran, so edits made by anyone else working in `cwd` appear too. A `read` turn
lists none. The list holds paths and sizes only, stops at 100 entries and reports how many
it left out.

`copy_to` keeps a file's path relative to `cwd`, leaves a file already in that folder
alone, and never replaces a different file: that entry carries `copy_error`.

The documentation now says what the sandbox allows: writes to `cwd` and to the system temp
folders.

## Upgrade

Install `claude-codex-bridge-v0.17.0.mcpb` and restart Claude Desktop.
