The 1M-context scripts stopped missing new models.

A fix release: the bridge itself, its six tools and the wire are unchanged from
v0.13.0. Only `scripts/enable-1m-context.sh` and `scripts/enable-1m-context.ps1`
changed, plus a test that now covers them.

## The catalog copy went stale, and said nothing

`enable-1m-context` builds its raised catalog from `models_cache.json`, the copy
codex fetches for itself. Setting `model_catalog_json` is what stops codex
refreshing that cache: with the override installed it serves the catalog file and
never calls `/models` again. So every re-run rebuilt from the snapshot taken the day
the override first went in, and a model that appeared afterwards was invisible to
it — GPT-6 Astra stayed at the stock 258,400 window while the script kept reporting
success, because its live check fell back to a GPT-5.6 seat that had been raised.

The scripts now lift the override for one `codex debug models` — a catalog fetch, no
model turn — rebuild from what that writes, and put the override back. A failure
after lifting restores the config as found.

## Also in this release

- The scripts print the cache's fetch date and the codex version that wrote it, and
  warn when the cache did not refresh (logged out, offline, or a CLI without `debug
  models`) instead of quietly copying an old one.
- A model family the script means to raise but cannot find in the fetched catalog is
  now named in a warning, rather than skipped in silence.
- `enable-1m-context.ps1` ran a `codex.cmd` shim through `cmd.exe /c` with quoting
  that came apart as soon as the quoted prompt joined the quoted shim path, so the
  verify step failed on an npm-installed codex on Windows. It now uses `/s` with the
  command line quoted as cmd expects. A native `codex.exe` install was never
  affected.
- `tests/enable_1m_sim.py` drives both scripts against a stand-in codex — no codex,
  no network, any OS — covering the stale-cache case, a missing family, a first run,
  a CLI too old for `debug models`, and config restoration after a failed run. It
  runs in CI on Linux and Windows.

Install: download `claude-codex-bridge-v0.13.1.mcpb` below. macOS: double-click it.
Windows: Claude Desktop → Settings → Extensions → Advanced settings → Install
Extension, from a local folder — Desktop refuses files on network paths, and Windows
has no `.mcpb` file association. Then restart Claude Desktop. Needs Python 3 on the
machine (`python3` on macOS, `python` on Windows) and codex installed before Desktop
starts. Prerequisites and the full documentation are in the
[README](https://github.com/Alexander-Stulov/claude-codex-bridge#readme).
